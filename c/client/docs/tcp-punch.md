# TCP 打洞与独立 NAT 映射检测

客户端保留 C ABI 1、非阻塞 `fastp2p_client_step` 和现有会话密钥、ACK 校验。Windows 继续后台静默启动。

## 检测与控制台

UDP 和 TCP 分别检测和决策。TCP 结果不再使用 UDP 类型作为替代值；TCP 未知时仍允许尝试直连。TCP/UDP 隧道还各自使用本次探测得到的公网地址，避免不同协议出口地址不同时相互覆盖。

TCP 默认从同一本地源端口访问网关 TCP 27180、27181。新版网关支持带换行边界的地址回显，避免把分片到达的端口前缀误认为完整端口。网关通过登录响应中的 `tcpProbeV2` 协商能力，旧网关和旧客户端仍支持原有回显方式。

可以通过配置或网关的按字段配置下发添加最多 4 个 **支持 STUN over TCP** 的服务器：

```json
{
  "network": {
    "TCPSTUNServers": [
      "stun1.example.net:3478",
      "stun2.example.net:3478"
    ]
  }
}
```

以上域名是占位示例，需要替换为实际可用服务。当前支持 IPv4 地址或域名，可省略端口，默认 3478。空数组只使用网关两个端口。参数解析不发起网络请求；可选服务器的 DNS 在 `start` 阶段解析，连接、请求和响应处理由后续 `step` 驱动。

每个目标等待最多 2 秒，目标数量最多 6 个；探测在后台进行，不等待 TCP 结果才上线。稳定/目标相关结果每 600 秒刷新，未知结果每 30 秒重试。一个批次保留源端口，解析标准 STUN 长度、事务 ID 和映射属性，拒绝畸形响应；所有探测套接字在完成、停止或销毁时关闭。

节点 API 和 SQLite 分别保存：

| 字段 | 含义 |
|---|---|
| `natType` | 保留的旧 UDP 映射字段 |
| `udpNatType` | UDP 映射类型：1 稳定、2 目标相关、3 递增、4 递减、314 未知 |
| `tcpNatType` | TCP 映射类型：1 稳定、2 目标相关、314 未知 |
| `tcpNatSamples` | 本轮成功的 TCP 映射样本数量 |
| `tcpNatDestinationIPs` | 成功样本涉及的不同目标 IP 数量 |

只有网关的同一 IP、多端口样本时，不能据此证明跨目标 IP 的映射也稳定。映射检测没有完整测试入站过滤行为，控制台明确区分“映射稳定”和传统 NAT1/NAT2/NAT3 分类。刷新 NAT 状态使用独立控制消息，不重放转发规则或配置。

网关自动将 SQLite schema 4 及以前的节点表迁移到 schema 5，增加 TCP 结果列并保留节点、规则和账号数据。旧记录的 TCP 值默认为未知；离线节点保留最后结果。部署前应按既有备份流程备份数据库，旧版网关不接受 schema 5。

## TCP 打洞时序

双方在连接请求和响应中协商 `tcpPunchV2`。双方支持时，流程为：

1. 各自探测并交换 TCP 公网映射，保持本轮的本地源端口。
2. 双方主动连接，尝试 TCP 同时打开。
3. 发起端主动连接最多尝试 1 次，每次最多 3 秒；失败后在同一源端口监听。
4. 响应端最多尝试 5 次，失败间隔随机 50–200 ms。每次使用同一个源端口，整个底层连接阶段最多 15 秒。
5. TCP 成功后继续现有隧道、会话密钥和 ACK 验证。实际接受/发起连接不会改变协议角色或会话所有者。
6. 超过预算后仍使用原有新会话重试和中继回退。中继节点筛选也按底层 TCP 或 UDP 各自的映射结果处理。

任一端不支持新能力时，使用原有监听加主动连接流程。双方为稳定映射且采用端口相关过滤的 NAT 时，此机制可用于 NAT3 对 NAT3；仍取决于 NAT/防火墙是否支持 TCP 同时打开、映射是否保持稳定，以及未匹配 SYN 是否被过早拒绝。不会修改本机或路由器的防火墙策略来提高成功率。

## TCP 转发半关闭

本次大包验收发现并修复了原有的方向混淆：本地读到 EOF 后，不能立即关闭整条转发连接，否则发送完请求并调用 `shutdown(SHUT_WR)` 的应用会丢失后续回包。

新版使用加密 `TUN_CLOSE` 消息中的可选 `writeEOF: 1` 表示单向结束。接收端先写完此前的数据，再关闭目标 socket 的写方向，同时继续读取响应。两方向均结束后才释放连接；半关闭连接空闲 300 秒后清理。旧版没有方向 EOF 能力，因此完整半关闭语义需要两端都升级，普通转发仍可与旧客户端互通。

## 验证方法和范围

单元测试覆盖分片 STUN、事务 ID、长度及端口边界、同源端口采样、TCP/UDP 决策隔离、多次真实连接及监听回退。SQLite 测试从没有 TCP 列的旧 schema 4 数据库迁移，再验证结果持久化。

隔离 NAT 测试使用两个独立 Linux SNAT 路由器，保持端口并按连接跟踪过滤入站。没有出站状态的入站 SYN 被静默丢弃，所有转发 UDP 均被阻断。通过多个公网地址的 TCP STUN 样本确认映射行为，并用真实 C 客户端进行认证和业务传输。测试还覆盖 UDP 困难映射诊断值与 TCP 稳定映射并存，以及可选旧客户端协商回退。

```sh
sudo unshare --net python3 c/client/tests/tcp_nat3_integration.py \
  --client /absolute/build/client/fastp2p \
  --gateway /absolute/build/gateway/fastp2p-gateway \
  --logs /absolute/private/test-output
```

脚本拒绝在宿主网络命名空间运行；子命名空间由测试进程持有，不创建宿主命名空间挂载。需要 Linux root、iproute2、iptables 和 OpenSSL。`--legacy-client /path/to/previous/fastp2p` 可额外验证旧版对端。

这属于具有真实 TCP/IP、NAT 和过滤规则的隔离仿真；运营商和实体路由器的成功率需要另行真机测量，不能从单元测试或仿真推导出普遍成功率。

### 2026-11-12 本地验证结果

- Linux ASan/UBSan：客户端 11 项、网关 5 项 CTest 通过，包括 SQLite 旧 schema 迁移与结果保留。
- 双 NAT 仿真：UDP 完全阻断和 UDP 困难映射诊断值两种场景均直接通过 TCP 传输；每种场景 3 次 256 KiB 半关闭回传逐字节校验通过。每端取得 4 个 TCP 映射样本，覆盖 3 个目标 IP。
- 旧客户端对端：能力回退及 3 次 256 KiB 普通回传通过，不将旧版计为支持方向 EOF。
- Linux：原生 QUIC、TCP/QUIC 中继、失败后自动转中继及恢复直连、SOCKS5 TCP/UDP 认证和并发、80 次握手断开循环通过。
- Windows：交叉编译、原生 TCP 检测和重试、会话密钥绑定、静默启动、身份持久化、TCP/QUIC SOCKS5 和配置同步/DPAPI 回归通过。
- 控制台：真实 C 客户端配置下发、确认、失败回滚和 NAT 双协议显示的浏览器端到端测试通过，并检查桌面和移动布局。

以上为 TCP 打洞功能发布前的本地验收结果。Android/macOS 的真机验证和运营商网络的穿透成功率尚未测试。

升级网关前应停止服务并备份 SQLite 数据库。回退到 2.0.7 时，必须同时恢复旧程序和升级前的数据库；仅替换程序不能回退 schema 5。完整 TCP 双向打洞和半关闭转发需要两端客户端都升级到 2.0.7。

客户端 2.0.6 和网关 2.0.8 的首次 CI 未通过，因此未发布稳定安装包。客户端 2.0.7 增加了 macOS 测试对完整重试周期的等待，网关 2.0.9 同步更新管理员持久化集成测试的 schema 断言。
