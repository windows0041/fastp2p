# 客户端缓冲优化记录（2026-11-12）

本轮优化 QUIC 接收缓冲和帧编码，保持现有协议、C ABI 1、配置及队列上限。基线为提交 `2e3ac119f117e137c0a46e8903448c54d64267d6`。

## 改动

- QUIC 接收改用环形缓冲。读取通过推进游标消费数据，跨边界时分两段复制；缓冲增长时才重新整理已有数据。
- 接收容量按需倍增，单隧道接收缓冲仍以 4 MiB 为上限。某些负载下会保留比原实现更多的容量余量，换取更少的扩容。
- 常规帧编码直接写入发送队列，去掉每帧的临时 `malloc` 和整帧复制。输入引用发送队列自身时仍保留临时副本，保证扩容、压缩后的字节兼容性。
- 通用缓冲的小容量分配受调用方指定上限约束，避免较小限额仍分配 4 KiB。

## 基准

环境：WSL Debian、Linux x86_64、GCC 14.2、Release 构建、仓库锁定的依赖。基线源码通过 `git archive 2e3ac11` 单独保存；两份源码使用完全相同的基准程序。前后顺序交替运行，各取 7 次的中位数。

基准调用实际接收回调、读取函数和帧编码函数，统计这些源码中的分配、复制及搬移。计时包含输出字节验证，范围为缓冲和组帧操作，不能推算端到端网速。

| 场景 / 指标 | 原实现 | 优化后 |
|---|---:|---:|
| 64 KiB 缓冲、16 KiB 读取，1000 轮总读取耗时 | 3.610 ms | 2.507 ms |
| 上述连续接收的扩容调用 | 55 | 5 |
| 上述读取时搬移剩余数据（memmove） | 98,304,000 B | 0 B |
| 4 MiB 缓冲、1 KiB 读取，总读取耗时 | 181.794 ms | 0.286 ms |
| 上述连续接收的扩容调用 | 3496 | 11 |
| 上述读取时搬移剩余数据（memmove） | 8,587,837,440 B | 0 B |
| 10 万帧、每帧 4 KiB，编码耗时（压力场景测次） | 11.253 ms | 8.279 ms |
| 上述常规编码的临时分配 | 100,000 次 | 0 次 |
| 上述编码的 memcpy 字节 | 820,000,000 B | 409,600,000 B |

64 KiB 场景的缓冲读取耗时约下降 30.5%，该组帧编码耗时约下降 26.4%。具体耗时随机器和负载变化；数据搬移量及分配次数更能反映本轮改动消除的工作。

## 验证

- Linux ASan/UBSan：10 项 CTest，包括接收缓冲环绕、带环绕数据扩容、复用、内存分配失败和满接收窗口；帧编码覆盖自引用、扩容、压缩、空帧及满队列。
- Linux 和 Windows 原生 QUIC 客户端/服务端互通及字节检查。
- Windows 原生缓冲、帧、C ABI/生命周期、会话密钥绑定、NAT 分类、SOCKS5 和 AEAD 测试。
- 六个 C 客户端的 TCP/QUIC、TCP/UDP 转发、半关闭、35 秒心跳及网关重启重连。
- SOCKS5 TCP/UDP、有无认证、并发目的端、错误处理及 80 次断开循环；TCP/QUIC 中继及对端重启恢复。

## 后续优先项

远程升级当前在控制消息处理中执行同步下载，慢网时会阻塞事件循环。下一轮适合用独立的异步下载状态机处理，并验证取消、失败和心跳。事件循环目前仅等待 WSS 描述符，数据通道使用至多 10 ms 的轮询；扩大事件等待范围需要同时覆盖 TCP/UDP 套接字与 QUIC 定时器，再测空闲 CPU、延迟和公平性。
